# 04 多服務串接與金鑰

> 狀態：部分實作。同帳號的服務綁定（書籤服務）已實作；HMAC 與 Access service token 尚未實作，目前沒有跨帳號的服務，服務自述（`describe()`／`call()`）也只定義了服務綁定這條路。

閘道的用途是讓一個 MCP 入口串接自己做的多個服務。每個服務依它在哪裡，選一種連線方式。

## 連線方式怎麼選

| 服務在哪裡 | 連線方式 | 要管的金鑰 |
|---|---|---|
| 同一個 Cloudflare 帳號的 Worker | 服務綁定 RPC（見 [02](02-服務綁定與RPC.md)） | 不需要 |
| 別的 Cloudflare 帳號、其他主機 | HTTPS + HMAC 簽章 | 每個服務一把 |
| 放在 Cloudflare Access 後面的服務 | HTTPS + Access service token | 每個服務一組 Client ID／Secret |

**每個服務各用一把金鑰**：某一把外流時只影響那個服務，換掉它不必動其他服務。

## HMAC 簽章

閘道用該服務的金鑰對請求簽章，服務端用同一把金鑰驗證。

閘道送出時加上這些 header：

```
X-Gateway-Timestamp: 1795219200        （秒）
X-Gateway-Nonce: <隨機字串>
X-Gateway-Signature: <base64url(HMAC-SHA256(key, 待簽字串))>
```

待簽字串：

```
METHOD \n PATH?QUERY \n TIMESTAMP \n NONCE \n SHA256(body) 的 hex
```

服務端依序檢查：

1. timestamp 與現在相差不超過 60 秒。
2. nonce 在這 60 秒內沒出現過（存 KV 或 D1，過期自動清掉）。只檢查 timestamp 擋不住 60 秒內的重放。
3. 用相同規則重算簽章，以等時比較（`timingSafeEqual`）比對。

在 Workers 上用 Web Crypto：

```ts
const key = await crypto.subtle.importKey('raw', new TextEncoder().encode(SECRET), { name: 'HMAC', hash: 'SHA-256' }, false, ['sign']);
const sig = await crypto.subtle.sign('HMAC', key, new TextEncoder().encode(payload));
```

### 金鑰的保存與輪替

- 兩端都用 `wrangler secret put` 保存（例如閘道的 `SVC_NOTES_KEY`，服務端的 `GATEWAY_KEY`），不寫進設定檔或程式碼。
- 輪替時服務端同時接受新、舊兩把（`GATEWAY_KEY`、`GATEWAY_KEY_PREVIOUS`），閘道換成新的之後再移除舊的。

## Access service token

服務已經放在 Cloudflare Access 後面時，可以不自己做簽章：在 Zero Trust 建一組 service token，閘道送出時帶 `CF-Access-Client-Id` 與 `CF-Access-Client-Secret` header，Access 在進入服務前就先驗證。代價是要多管一份 Access policy。

## 命名規則

| 項目 | 規則 | 例 |
|---|---|---|
| tool 名稱 | `<服務>_<動作>` | `bookmarks_search`、`bookmarks_add` |
| 授權範圍 | `<服務>:read`、`<服務>:write` | `bookmarks:read` |
| 額外範圍 | 有成本或對外動作的操作另開，`<服務>:<動作>`（見 [06](06-安全與權限.md)） | `<服務>:send` |
| binding 名稱 | 服務名大寫；閘道把它轉小寫當服務名稱 | `BOOKMARKS` → `bookmarks` |
| 金鑰名稱 | `SVC_<服務>_KEY` | `SVC_NOTES_KEY` |

前綴讓 AI 分得出 tool 屬於哪個服務，也讓閘道能依前綴對應到授權範圍。tool 與範圍由服務自己在 `describe()` 宣告（見 [02](02-服務綁定與RPC.md)〈服務自述〉），前綴由閘道強制：不是自己服務名稱開頭的 tool 與範圍，閘道直接丟掉。

## 新增一個服務的步驟

1. 服務端提供只含資料操作的介面：同帳號匯出 `WorkerEntrypoint`，否則開一組驗 HMAC 的內部路由。
2. 服務實作 `describe()` 與 `call()`：tool 名稱加上服務前綴，讀寫分別對應 `:read`、`:write`；有成本或對外動作的另開動作範圍。參數在服務這邊驗證。
3. 閘道在不進版控的 `wrangler.jsonc` 加上 binding，並把 binding 名稱加進 `SERVICES`（本機 `.dev.vars`、線上 secret）。閘道的程式不必改，repo 裡也不留這個服務的資訊。
4. 同意頁會依 `describe()` 的 `scopes` 自動多出該服務的勾選項目。
5. 用 MCP Inspector 確認：沒勾選該服務的 token，在 `tools/list` 裡看不到它的 tools。
