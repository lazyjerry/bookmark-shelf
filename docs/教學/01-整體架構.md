# 01 整體架構

> 狀態：已實作（閘道 repo 與書籤服務的 `BookmarkRpc`），Passkey 登入尚未進行。tool 由服務自述（`describe()`／`call()`），書籤服務與閘道都已實作。

## 目標

讓 AI client（Claude、ChatGPT、Cursor 等）透過 MCP（Model Context Protocol）操作自己做的各種服務。登入與授權集中在一個閘道，各服務只管自己的資料。書籤服務是第一個接上的服務。

## 角色

```
                    ┌───────────── 閘道網域 <閘道網域> ─────────────┐
AI client ──OAuth──▶│ MCP 閘道 Worker                               │
          ──MCP────▶│  ・OAuth 授權伺服器（登入、同意、發 token）   │
                    │  ・MCP server（tools 由服務自述、依權限過濾） │
                    └──────┬──────────────────────┬─────────────────┘
                           │ 服務綁定 RPC          │ HTTPS + HMAC
                           │（同一個 Cloudflare     │（別的帳號或
                           │  帳號，不經公網）      │  非 Cloudflare）
                           ▼                       ▼
                  書籤 Worker（bookmark-shelf）   其他自建服務
                  ・BookmarkRpc entrypoint        ・各自一把金鑰
                  ・D1、Workers AI、通知信
```

| 角色 | 負責 | 不負責 |
|---|---|---|
| MCP 閘道 | MCP 協定、OAuth、你本人的登入、依授權範圍決定能用哪些 tool、呼叫紀錄 | 任何服務的資料與商業邏輯；各服務有哪些 tool、哪些範圍 |
| 書籤服務 | 書籤的驗證、寫入、AI 整理、通知信、webhook；描述自己的 tool 與授權範圍、驗證 tool 的參數 | MCP、OAuth、閘道的登入 |

## 一次呼叫的流程

1. AI client 第一次連 `<閘道網域>/mcp`，收到 401，依 OAuth metadata 走授權流程。
2. 閘道的授權頁要你登入（閘道自己的密碼或 Passkey），再勾選這個 client 能用哪些服務、哪些權限。
3. 閘道發 access token 給 client，token 綁著你勾選的範圍（例如 `bookmarks:read`）。
4. client 帶 token 呼叫 `tools/call`，例如 `bookmarks_search`。
5. 閘道檢查範圍，透過服務綁定呼叫書籤 Worker 的 `BookmarkRpc.call('bookmarks_search', 參數, 呼叫者)`。有哪些 tool、各需要什麼範圍，是閘道先前呼叫 `describe()` 向書籤服務要來的（見 [02](02-服務綁定與RPC.md)〈服務自述〉）。
6. 書籤 Worker 查 D1、回傳純資料；閘道包成 MCP 回應交給 client。

## 為什麼這樣切

- **登入只做一次**：閘道是你所有服務的入口，用一套登入、一份授權清單管理所有 AI client。各服務不必各自實作 OAuth。
- **閘道用獨立網域**：閘道不屬於任何一個服務，日後串接更多服務時不必綁在書籤服務的網域上。代價是書籤服務的 Passkey 與登入 Cookie 不能沿用，閘道要有自己的登入（見 [03](03-閘道登入與OAuth.md)）。
- **服務之間走服務綁定 RPC**：同一個 Cloudflare 帳號內的呼叫不經公網，RPC 方法也沒有 HTTP 入口，外部打不到，不需要另外管金鑰（見 [02](02-服務綁定與RPC.md)）。
- **服務保持精簡**：MCP SDK、OAuth 套件、KV 都只在閘道。書籤 Worker 只多一份 tool 定義與驗證參數用的 zod。
- **閘道不認識任何服務**：tool、授權範圍、參數格式都由服務自己描述，閘道 repo 裡沒有服務專屬的程式，接上哪些服務寫在 secret 裡。新增或調整 tool 只要部署該服務。

## 與現有存取方式並存

閘道上線後，書籤服務原本的存取方式照舊：瀏覽器登入、應用程式帳密的 REST API、Apple 捷徑、VS Code 延伸模組。RPC 是多開的一個內部入口，不取代 REST。
